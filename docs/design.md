# ShallowImagine 设计说明

日期：2026-11-11
状态：已实现（v0.1.0）

## 1. 问题

当前 agent 的主流叙事是"更准、更快、更有用"。这个项目反着来：做一个**故意很烂**的 agent，
它的回答表面上与问题高度相关，结构完整、术语密集、语气笃定，但深层是**范畴错误**——
把 A 领域的本体、单位、因果链，硬接到 B 领域的问题上。

参考原型是中文互联网梗「42 号混凝土拌意大利面」：被催婚的人不谈婚姻，转而用土木工程的
配比、标号、养护期来回答，亲戚听不出破绽，但每一句都不成立。

目标不是随机噪声，而是**可复现、可解释、可训练的胡说八道**。

## 2. 目标与非目标

### 目标

1. 给定任意中文问题，输出 150–400 字的"一本正经的错答"。
2. 错误类型可命名、可追踪：每条回答都知道自己误读了哪个领域、用了哪些算子。
3. 核心 harness 零依赖、可离线运行，不需要任何模型或 API key。
4. 能在普通笔记本 CPU 上，用 0.6B 级模型完成 LoRA 风格迁移。
5. 对高风险话题保留荒诞、去掉可执行细节。

### 非目标

- 不追求回答正确、有用、安全可执行。
- 不追求通用对话能力、多轮记忆、工具调用。
- 不追求 benchmark 分数；评测只验证"表面相关 + 深层错位 + 高置信"。
- 不做面向公众的欺骗性产品。

## 3. 核心概念

### 3.1 范畴错误，而不是事实错误

事实错误是"北京是日本首都"；范畴错误是"你的婚姻需要按 GB 50010 做抗压强度复核"。
后者更难被察觉，因为它保留了问题的名词、数字和情绪，只在**本体层**发生错位。

三个可操作维度：

- **表面相关**：问题中的名词、数字、场景在回答中被复述。
- **深层错误**：回答的谓词、单位、评价标准来自另一个领域。
- **过度自信**：没有犹豫词、免责声明、反问，只有断言和结论。

### 3.2 领域邻接图

两个领域相邻，当且仅当它们**共享一个属性**、但**不共享本体**：

```
civil    --(配比与养护)--> cooking
finance  --(周期与预测)--> weather
auto     --(诊断与保养)--> medicine
programming --(模板与版本)--> printing
```

共享属性提供"听起来有关"的桥；本体差异提供"一细看就错"的落差。
这是整个笑话的物理引擎。

### 3.3 先 harness，后模型

两条路线：

- **B：直接微调大模型** —— 成本高，风格不可控，错误类型不可解释。
- **A：Harness 先行 + 蒸馏**（采用）—— 确定性 harness 生成 SFT 数据，
  小模型只学"语气和句式"，错误结构由数据保证。

选 A 的理由：0.6B 模型容量有限，让它同时学会"相关"和"错位"很难；
但让它模仿一批已经同时满足两者的样本，是可行的。

## 4. 架构

### 4.1 八节点流水线

| # | 节点 | 输入 | 输出 | 职责 |
| --- | --- | --- | --- | --- |
| 1 | Parse | 原始文本 | `SceneCard` | 话题、实体、数字、领域打分、情绪、问句类型 |
| 2 | Tether | 场景卡 | 2 句正常锚点 | 保证回答仍然"接着问题说" |
| 3 | Misread | 场景卡 + 邻接图 | 目标领域 + 共享属性 | 选择"错得合理"的领域 |
| 4 | Transplant | 场景卡 + 领域 | 4–5 条 `Claim` | 用算子生成错误命题 |
| 5 | Fluency | 草稿 | 润色稿 | 可选模型后端；只改流畅度，不改事实 |
| 6 | Confidence | 草稿 | 断言化文本 | 删犹豫、加断言、补结论 |
| 7 | Persona | 文本 | 人格化文本 | 开头 + 结尾，不改正文 |
| 8 | Guard | 场景卡 | 安全决策 | 高风险话题切换荒诞模式 |

流水线对 `(question, seed)` 确定性，因此同一输入可复现，也可作为数据生成器。

### 4.2 数据模型

```python
SceneCard(raw, topic, topic_key, entities, numbers, domain_scores,
          primary_domain, question_type, emotion, guarded, guard_groups)

Claim(text, operator, violations=1)

Result(text, meta)   # meta 含 topic / target_domain / operators / metrics
```

`Result.meta` 是项目的可解释性接口：任何一条输出都能说清楚"它把什么误读成了什么"。

### 4.3 六个算子

| 算子 | 作用 | 失败模式 |
| --- | --- | --- |
| `domain_transplant` | 重新定义问题的本体 | 领域选得太远，听起来完全无关 |
| `unit_mismatch` | 借用错误单位/阈值/概率 | 单位太突兀，像随机符号 |
| `causal_inversion` | 颠倒因果并加码自信 | 句子过长，逻辑不可读 |
| `fake_specificity` | 伪造标准号、条款、样本量 | 数字过多，变成噪声 |
| `register_lock` | 锁定行业语域 | 开头堆叠，节奏拖沓 |
| `category_collision` | 本体硬拼成短语 | 语法不通，笑点变成病句 |

每个算子独立、可单测；出问题时可定位到具体算子。

### 4.4 后端

- `template`：默认，零依赖，确定性。
- `llama`：任何 OpenAI 兼容端点（llama.cpp / vLLM / Ollama 兼容层）。
- `hf`：本地 transformers 模型，可挂 LoRA adapter。

两种模式：

- `harness`：模型只润色草稿（保结构、保安全）。
- `standalone`：微调后的模型直接回答；高风险输入强制回退到 harness。

## 5. 数据

### 5.1 种子

- 人工种子 69 条，覆盖催婚、职场、情感、生活、技术、学习、身体、社会。
- 弱智吧标题 2000 条，过滤后保留 90 条问句（长度 8–40 字，去掉吧务/敏感话题）。

### 5.2 生成

每条种子生成多个变体，按以下条件过滤：

- 未触发 guard（默认）；
- `relevance >= 0.35`；
- `repetition <= 0.25`；
- 长度 120–600 字；
- 回答去重。

输出格式为 chat messages + `meta`，meta 保留算子与领域信息，便于审计和分层采样。

### 5.3 训练

- 基座：Qwen3-0.6B（Apache-2.0，中文强）。
- LoRA：r=16，alpha=32，dropout=0.05，target 为 attention + MLP 投影。
- CPU 配置：fp32、batch=1、grad_accum=8、gradient checkpointing、seq 512。
- Loss 只算 assistant token；优先使用 chat template 的 assistant mask。

## 6. 评测

自动指标：`relevance`、`domain_density`、`assertive_rate`、`hedge_rate`、`repetition`、长度。
人工评分：相关度、范畴错误强度、自信度、幽默度、安全性（1–5）。

自动指标只做回归哨兵：相关度不能塌，重复率不能爆，犹豫率必须接近 0。
真正的"好不好笑"必须人看。

## 7. 安全

高风险组：medical、legal、finance、safety、self_harm。

触发后：

1. 跳过 `fake_specificity`（不伪造剂量、条款、步骤）；
2. 目标领域限制在低风险荒诞领域（土木、烹饪、天文、印刷）；
3. 仍然保留"自信 + 错位"的语气，但去掉可执行细节；
4. CLI/JSON/网页都暴露 `guarded` 标志；
5. 网页顶部固定免责声明。

这不是内容审核系统，只是把"可能被当真并造成伤害"的部分拿掉。

## 8. 关键决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 错误轴 | 范畴错误 | 比事实错误更隐蔽、更幽默、更难被 0.6B 学会 |
| 生成方式 | 确定性模板 | 可复现、可单测、零成本、结构化可解释 |
| 模型路线 | Harness → SFT | 小模型只学风格，结构由数据保证 |
| 模型规模 | 0.6B | CPU 可训练；再大没有性能收益 |
| 后端 | 可插拔 | 没有模型也能 demo；有模型可增强流畅度 |
| 安全 | 保留荒诞、去掉细节 | 不破坏笑点，同时降低误用风险 |

## 9. 已知限制

- 模板句法有限，长对话会重复句式；需要更多模板或模型润色。
- 领域识别依赖关键词，遇到新词会退化为随机安全领域。
- 自动指标测不出"好笑"，人工评测规模还很小。
- 0.6B 在 standalone 模式下容易丢失数字和标准号，需要更多数据与更长训练。
- 目前只支持中文。
